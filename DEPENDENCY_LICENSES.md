# Dependency license metadata checks

`licenses:check` is a mandatory quality and pre-push/CI gate. It inventories installed runtime and development dependencies, transitive dependencies and installed peers, including private dependencies. It supports the repositories' npm, pnpm and Yarn node_modules layouts. Required missing packages fail; missing optional architecture packages are allowed. Frozen lockfile installation remains the source of version/integrity reproducibility.

The gate compares exact declared license expressions with `dependency-licenses-policy.json`. New expressions fail. Missing, malformed, unknown or file-referenced metadata fails unless its exact package name, version, declaration and reason is explicitly recorded as an existing **unresolved** review item. LGPL/EPL/MPL/FSL/CC-BY declarations also require an exact unresolved review record and warn on every run. A new version needs a new review. Recorded observations are drift evidence; they are not legal approval, a choice between dual-license alternatives, or permission to redistribute.

There is no automatic policy writer or approval command. Review dependency and policy diffs together. Investigate upstream license text, use/distribution conditions and required notices before resolving an item; do not invent licenses or change third-party metadata to make checks pass. Existing missing metadata and conditional declarations remain visible in the committed policy and every check's warnings. Owner/legal review and required distribution notices remain release work tracked by the existing legal/privacy stories.

Architecture-specific optional packages can differ between macOS and Linux. The gate therefore compares declarations and exact unresolved findings rather than requiring identical installed package sets. Synthetic filesystem tests cover nested, scoped, symlinked and pnpm virtual-store resolution, cycles, missing dependencies and malformed metadata. Pure policy tests cover drift, unknown/new versions, warnings, malformed policies and platform variation; gate self-tests prevent removing the check.

Scope is declared package metadata, not a legal audit or a full software bill of materials. Yarn PnP is unsupported (these repositories use node_modules). Native OS/SDK licenses, vendored code, copied assets, notices and provider terms require separate release review. No runtime dependency or application behavior changes as part of this tooling delivery.

## Python scopes

`licenses:python:check` additionally runs after package build. It reads all installed quality distributions (excluding pip/setuptools/wheel) and the rotation ZIP's dist-info metadata without executing archive code. Python 3.12 quality dependencies include pinned transitives. The policy is `scripts/python-license-observations.json`; new exact declarations or missing metadata fail, with explicitly unresolved findings always reported. License-Expression takes precedence over literal classifiers, then short legacy License fields. Long or unusable metadata is reported as missing, never guessed. Use `.venv-quality/bin/python3 scripts/check-python-licenses.py --inventory` for the safe name/version/declaration report; this does not update policy or approve licenses.
